# OGE LAB 2027 · Тренажёр + личные кабинеты

> **Статус: личные кабинеты временно отключены (15 ноября 2026).** На публичном сайте работают только Главная, Грамматика, Лексика и Словообразование. Регистрация, вход, сбор аккаунтов и передача результатов в API не выполняются из интерфейса. Исходники `assets/account.js`, `assets/account.css`, `privacy.html`, а также серверный код оставлены в репозитории для будущего возвращения функции. Инструкция ниже описывает отложенную реализацию, а не действующую регистрацию.


Публичный сайт: HTML/CSS/JS. Приватный API: **Cloudflare Workers + D1**. Источник кода может храниться в открытом репозитории; **реальные никнеймы учеников, пароли, сессии и учебные результаты НЕ помещаются в GitHub, JavaScript или исходные файлы**.

## Возможности

- Грамматика — 75 вариантов, лексика — 75 вариантов, словообразование — 157 семейств.
- Светлая и тёмная темы, компактный интерфейс, озвучка, верхний и нижний выбор вариантов.
- Регистрация по **Telegram-нику** (обязательно), **паролю** от 12 символов (обязательно), **имени** (необязательно) и согласию на обработку данных.
- Личный кабинет: история проверок, правильные ответы/ошибки по заданиям, точность по разделам, график активности, трудные варианты, смена имени и пароля, выгрузка данных и удаление аккаунта.
- Кабинет администратора: количество зарегистрированных учеников и проверок, статистика учащихся и индивидуальные отчёты по попыткам. Доступ защищён серверной ролью `admin`.
- Результаты считаются **на сервере** по ключам, не по присланным браузером «готовым баллам».

## Что где хранится

| Данные | Место | Кому доступны |
| --- | --- | --- |
| Код, задания, правильные ответы | GitHub (публично) | Всем, кто видит репозиторий |
| Telegram-ник, имя, хеш пароля, время входа | Приватная Cloudflare D1 | Только сервер; ученику — свой профиль, администратору — ник/имя/время (не хеш) |
| Оценки, дата, ошибки по заданиям | Приватная D1 | Ученик и администратор |
| Вводимые слова (черновики) | `localStorage` на устройстве | Пользователь этого браузера; не синхронизируются |
| Секрет защиты лимитов | Cloudflare Worker Secret | Только сервер, не GitHub |

Пароли **никогда не хранятся в открытом виде**: PBKDF2-HMAC-SHA256, 600 000 итераций, случайная соль для каждого пользователя. Сессионный токен хранится в `HttpOnly`, `Secure`, `SameSite=Strict` cookie; сервер хранит только SHA-256 его случайного значения. Нет открытого пользовательского API для чтения чужих результатов. Подключать API нужно на том же домене, что и интерфейс.

> **Важно:** буквальная гарантия «никто, кроме администратора и ученика» недостижима для любого облачного сервиса: инфраструктурный провайдер и законные полномочия доступа остаются вне контроля приложения. Telegram-ник — **логин, а не доказательство владения Telegram**. Для подтверждения личности потребуются Telegram Login/Bot и отдельный секрет; в этой версии они не настроены. Защита несовершеннолетних и содержание политики требуют юридической проверки до публичного запуска.

## Почему на GitHub Pages регистрация не активна

GitHub Pages раздаёт только статические файлы. Там можно пользоваться заданиями; пункт **«Кабинет» покажет, что защищённый сервер не подключён**, и не позволит отправить пароль. Это намеренная защита, а не ошибка.

Для реальных аккаунтов сайт **вместе с API и базой** надо разместить в Cloudflare Workers (домен `*.workers.dev` или собственный домен). GitHub при этом остаётся репозиторием исходников, **но не базой данных**. Не включайте регистрацию с фальшивым хранением в `localStorage` или в публичном JSON-файле.

## Развёртывание (только владельцу)

Нужен ваш Cloudflare-аккаунт с правами на Workers + D1. **Для выбранной безопасной парольной хеш-функции рекомендуется Workers Paid:** бесплатный тариф ограничивает процессорное время запроса 10 мс, и регистрация/вход с 600 000 итераций PBKDF2 могут не укладываться в этот лимит. Проверьте условия тарифа до запуска. Не передавайте пароли и API-ключи в переписке и не помещайте их в репозиторий.

1. Установить [Node.js](https://nodejs.org/) и выполнить `npm install`, затем `npx wrangler login` (авторизация в Cloudflare через браузер).
2. Создать пустую приватную базу: `npx wrangler d1 create oge-lab-private`.
3. Скопировать выданный **`database_id`** в поле `d1_databases[0].database_id` файла `wrangler.jsonc`. Идентификатор базы сам по себе не даёт доступ к данным; секреты туда не писать.
4. Создать и применить таблицы: `npx wrangler d1 migrations apply oge-lab-private --remote`.
5. Задать секрет для защиты лимитов доступа: `npx wrangler secret put RATE_LIMIT_SECRET` и ввести **случайную длинную строку** (минимум 32 случайных байта). Он хранится в секретах Cloudflare, не в коде.
6. Выполнить `npm run deploy`. Скрипт сначала создаст папку `public/` **только с публичным сайтом**, затем загрузит API и статику. Серверный код, конфигурация, тесты и миграции **не становятся статическими файлами сайта**.
7. Открыть полученную ссылку `https://…workers.dev` (или свой домен) и проверить `/api/health`: ожидать `{"ready":true}`. Только здесь регистрация включится.

### Как назначить себя администратором

- **Лично** зарегистрируйтесь на рабочем домене со своим Telegram-ником и паролем.
- Убедитесь, что ник принадлежит именно вам: **ник не проверяется через Telegram автоматически**.
- Из своего авторизованного Cloudflare-аккаунта выполните SQL, заменив `your_telegram_username` на ник **без @ и в нижнем регистре**:

```bash
npx wrangler d1 execute oge-lab-private --remote --command="UPDATE users SET role='admin' WHERE telegram='your_telegram_username';"
```

- Выйдите и войдите снова — появится вкладка **«Ученики»**. Ни регистрация, ни знание чьего-либо ника сами по себе **не дают** роль администратора.

## Текущие ограничения

- Результат сохраняется в D1 **после нажатия «Проверить ответы»**. Неотправленные черновики остаются на устройстве и между браузерами не синхронизируются.
- Сохранены только статусы по заданиям (`correct`, `wrong`, `empty`), без вводимых текстов.
- История для аналитики считывает до 500 последних проверок на одного ученика; экспорт выгружает все попытки.
- **Нет автоматического восстановления пароля**, потому что адрес электронной почты не запрашивается, а Telegram-ник не подтверждается.
- До реального развёртывания сервер и база существуют **только как код и схема**, настоящие данные не собираются.
